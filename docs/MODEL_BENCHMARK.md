# A01 — локальная модель на ASUS ROG G18 G814JIR

Дата измерений: 01.11.2026. Это отчёт реальных прогонов на серверном ноутбуке,
а не оценка по названию RTX 4070 Laptop. Сравнение, видимая mock-сцена, SQL-очередь и модели без внешних маршрутов
проверены. Физические LAN/Wi-Fi-off игровые показы ещё не проведены.

Фоновые приложения пользователя не закрывались; нагрузка и доступная RAM менялись.
Во время подготовки запускались Go-проверки;
первичное сравнение не является лабораторным измерением в простое. Память
Windows под нагрузкой заметно меняется: последующий snapshot показывал свободными
2 797 988 КиБ. Свободная RAM хоста и WSL — разные показатели; swap/общую память
Windows не следует считать дополнительной dedicated VRAM.

Runtime установлен в bin/ollama-runtime (около 2,4 ГиБ), веса — data/ollama/models
(около 5,2 ГиБ). Оба каталога игнорируются Git. Архив Ollama размером
1 525 346 571 байт проверен по SHA256
`c9490e0f520be21271d969e6703f012268b1d39f8b70dd58854e5bfef7a75bb6`.
Windows-драйвер не обновлялся, Linux GPU-драйвер не устанавливался.

Проверялись окна 8192 и 16384 токена, temperature=0.2. Производные tags
`gallery-bench-qwen3-4b:<окно>`, `gallery-bench-qwen25-3b:<окно>` и
`gallery-bench-qwen25-15b:<окно>` созданы локально из указанных базовых tags.
Они разделяют веса; дополнительные многогигабайтные копии не скачиваются.
Qwen3 проверяется с штатным reasoning, без скрытого отключения только в benchmark.

Воспроизведение и точные русские вопросы — [tools/modelbench](../tools/modelbench/README.md).
Семь запросов в серии: два профиля, completed-память, чистая история, затем вход
16000 символов с canary в начале. Этот русский вход занял 5007 токенов у Qwen3
и 5026 у Qwen2.5. Оба окна сохранили canary при первичном сравнении. Это не
доказательство вместимости любого входа из 16000 Unicode-кодовых точек.

TTFT — время до первого видимого текста, включая reasoning и загрузку;
tokens/s — eval_count/eval_duration Ollama (может учитывать reasoning).
Полное время измеряется от начала HTTP-запроса до done/ошибки, не включает
финальное чтение датчиков. Память — system-wide sampled peak: NVIDIA, WSL
total−available и Windows total−free. Дискретный опрос даёт нижнюю оценку пика.
Неизвестные показатели — null. OOM подтверждается сообщением модели/журналом,
а не предполагается по любой HTTP-ошибке. Сброс файлового кеша ОС не выполняется.

### Сравнение холодного runner и повторов

В каждой cold-серии 7 запросов с выгрузкой runner перед каждым вопросом;
файловый кеш ОС не очищался. До серии предыдущая модель выгружена, поэтому
пики не включают её GPU-память. Повторы — 21 запрос на конфигурацию, temperature=0.2,
без фиксации seed. Скорости/времена не обещаются для произвольного вопроса.

\* Только доступные метрики из done успешных ответов; у прерванного ответа
load/eval может быть null. В конфигурации Qwen2.5 1.5B/16384 два раза обнаружен
output_limit (по одному в повторах и cold, 8002 кодовые точки при получении chunk).

Первичные 42 и повторные 126 запросов использовали менее строгий header deadline
инструмента. Их completed не доказывает совместимость с 10s headers production.
Cold, scene и offline используют исправленный клиент: 5s dial, 10s headers,
90s total, production-проверки Unicode/role/NUL и output limit. Регрессии покрыты
fake HTTP-тестами, финальные tags также проверены настоящим production adapter.
Все первичные данные, включая эти ограничения и отказы, сохранены в JSONL.

### Видимая Three.js-сцена

Источник — [fix/day2-first-demo](https://github.com/ManInTheCoat/Hope-Merge-Frontend/tree/2e763e8e9e63f8909bd15077b9ab66178fd64ea7),
SHA `2e763e8e9e63f8909bd15077b9ab66178fd64ea7`. Отдельный временный профиль Edge 156,
localhost:5173, viewport 1578×910, DPR=1.25, canvas 1972×1137, 9–10 текстур и 27–28
геометрий. Canvas снят и визуально проверен: зал, три изображения и гид отрисованы.
Вкладка оставалась visible; наблюдения видимости/фокуса сохранены. В копию в /tmp
добавлены только синтетический автологин и наблюдатель WebGL/rAF; исходный frontend
не менялся. Рендер продолжает работать и без pointer lock.

Renderer: `ANGLE (Intel, Intel UHD Graphics, Direct3D11)`, а не NVIDIA. Это
проверенное распределение GPU в данном запуске. При переносе браузера на NVIDIA,
другом MUX/питании/контенте или большей фоновой нагрузке повторить матрицу;
данный отчёт не подтверждает производительность будущего полноценного мира C01.
Синтетические ответы frontend-моков не использовались как доказательство работы LLM.

### Реальная SQL-очередь со сценой

Opt-in `TestModelBenchmarkQueue`, отдельная PostgreSQL 18.6 и собственная schema.
Три синтетических владельца, штатный Store/worker/Context/Ollama adapter, FIFO
без перекрытия, completed и память сохранены. Admission/HTTP/WS игрового клиента
здесь не подменяются утверждением о полном показе. Времена очереди/выполнения
получены из сохранённых timestamps; TTFT — от started до первого delta.

## Выбор, офлайн-проверка и границы приёмки

**Основной: gallery-guide-main:a01 = Qwen3 4B Q4_K_M, num_ctx=8192, temperature=0.2.**
Более связные русские объяснения в ручном просмотре, достаточный запас до 90 с,
а окно 8192 экономит около 1,1 ГиБ NVIDIA VRAM относительно 16384 в cold-прогонах.
Проверенный длинный русский вход помещается. **Резерв: gallery-guide-reserve:a01 =
Qwen2.5 1.5B Q4_K_M с теми же окном/temperature** — ниже память и задержки, но
заметно хуже качество. Qwen2.5 3B быстрее основного, однако встречались неверные
интерпретации личного кода; выигрыш качества над меньшим резервом не стал основанием
заменить Qwen3. Эти наблюдения не являются автоматическим рейтингом фактической точности.

В память-сценариях код восстановлен из completed-пары, а в чистой истории чужой
код не появился. У 1.5B встречались выдуманные названия картин/повтор вопроса.
У всех моделей бывают пропуски явного обозначения реконструкции. Для учебного
контента C01 нужна отдельная проверка фактов/инструкций; prompt не гарантирует
их соблюдение. Частичные/неуспешные ответы не объявляются памятью.

Локальные manifest digest подготовленных aliases (совпадают с измеренными
bench-aliases 8192):

- main: `01dccbec213a6c7f3483c736f329b0b9e60581c89acfd64e1b0f490ca800a812`;
- reserve: `403c6fd5cd375b3952875a5f42c6e05926c3a191521276580703968491733991`.

Оба заранее скачанных варианта прошли [offline.sh](../tools/modelbench/offline.sh)
в namespace с единственным lo, пустыми IPv4/IPv6 routes и отказом внешнего curl.
Production-adapter fixtures: по 4 реальных ответа каждой модели, затем по 7
benchmark-запросов; всё completed/PASS без скачиваний. Во время offline-прогона
сцена оставалась открыта на хосте. API ps подтвердил окно 8192 и полное размещение
на GPU: main 4 001 072 414 байт, reserve 1 367 059 988 байт (`size == size_vram`).
Это размер runner по Ollama, не общий пик VRAM системы из таблиц.

**Физические LAN-показ без WAN и localhost-показ с выключенным Wi-Fi ещё не проведены.**
Namespace подтверждает автономность весов/адаптера, но не полный игровой показ
C01/Q02, не сетевую доступность остальных ноутбуков и не бюджет контента frontend.
Сеть Windows не переключалась. При изменении режима GPU/питания/нагрузки/мира
повторить измерения; аппаратные гарантии для иных условий не заявляются.

Defaults и точные команды скачивания, проверки digest, создания aliases и ручного
офлайн-переключения — [DEVELOPMENT.md](DEVELOPMENT.md#a01--подготовка-ollama-в-wsl-ubuntu),
[Modelfile](../configs/ollama/main.Modelfile) и [резерв](../configs/ollama/reserve.Modelfile).
Backend не скачивает модели и не переключает их автоматически; API, миграции,
90/120 секунд и 8000 выходных символов не изменены.
