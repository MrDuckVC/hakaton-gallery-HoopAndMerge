# A01 — локальная модель на ASUS ROG G18 G814JIR

Дата измерений: 01.11.2026. Это отчёт реальных прогонов на серверном ноутбуке,
а не оценка по названию RTX 4070 Laptop. Исправленный сценарий проверен в baseline и SQL-очереди.
Сцена частично была hidden; повторная офлайн-матрица прервана по просьбе пользователя. Физические LAN/Wi-Fi-off игровые показы ещё не проведены.

Проверялись окна 8192 и 16384 токена, temperature=0.2. Производные tags
`gallery-bench-qwen3-4b:<окно>`, `gallery-bench-qwen25-3b:<окно>` и

Они разделяют веса; дополнительные многогигабайтные копии не скачиваются.
Qwen3 проверяется с штатным reasoning, без скрытого отключения только в benchmark.

Воспроизведение и точные русские вопросы — [tools/modelbench](../tools/modelbench/README.md).
Семь запросов в серии: два профиля, completed-память, чистая история, затем вход
16000 символов с canary в начале. Этот русский вход занял 5007 токенов у Qwen3
и 5026 у Qwen2.5. Оба окна сохранили canary при первичном сравнении. Это не
доказательство вместимости любого входа из 16000 Unicode-кодовых точек.

TTFT — время до первого видимого текста, включая reasoning и загрузку;
tokens/s — eval_count/eval_duration Ollama (может учитывать reasoning).
Полное время измеряется от начала HTTP-запроса до done/ошибки, не включает
финальное чтение датчиков. Память — system-wide sampled peak: NVIDIA, WSL
total−available и Windows total−free. Дискретный опрос даёт нижнюю оценку пика.
Неизвестные показатели — null. OOM подтверждается сообщением модели/журналом,
а не предполагается по любой HTTP-ошибке. Сброс файлового кеша ОС не выполняется.

### Исправление review: completed-pairs-v2

[Замечание P2](https://github.com/MrDuckVC/hakaton-gallery-HopeAndMerge/pull/33#discussion_r4434030603)
подтвердилось: пустые ID заставляли Context.Build исключать все completed-пары.
Во втором вопросе оставалась только Summary. В протоколе v2 у каждого вопроса
свой ID по repeat/profile/index; после успешного первого ответа follow-up получает
5 сообщений, включая полный
прошлый user/assistant, а старт/чистая история — 3 сообщения без прошлого assistant.
Регрессионный fake HTTP-тест проверяет точный текст полной пары, включая хвост
ответа за пределами Summary, обе личности и два повтора. До исправления он
падает на четырёх follow-up (3 вместо 5 сообщений); после — проходит с race.

Таблицы пересчитаны по новым завершённым измерениям: cold 42, повторы 126,
сцена 63. Дополнительный offline-прогон прерван по просьбе пользователя сократить
работу; его завершённые строки сохранены отдельно по phase в общем JSONL. Первый A01 сохранён отдельно:
[287 legacy измерений](model-benchmark/legacy-summary-only-results.jsonl) и
[legacy environment](model-benchmark/legacy-summary-only-environment.json).
Его Summary-only данные не используются для подтверждения полной истории и
текущего выбора профиля. Числа между протоколами не сравнивать как выигрыш скорости.

### Three.js-сцена: ограничения видимости

SHA `2e763e8e9e63f8909bd15077b9ab66178fd64ea7`. Отдельный временный профиль Edge 156,
localhost:5173, viewport 1578×910, DPR=1.25, canvas 1972×1137, 9–10 текстур и 27–28
геометрий. Canvas снят и визуально проверен: зал, три изображения и гид отрисованы.

данный отчёт не подтверждает производительность будущего полноценного мира C01.

### Реальная SQL-очередь со сценой

Opt-in `TestModelBenchmarkQueue`, отдельная PostgreSQL 18.6 и собственная schema.
Три синтетических владельца, штатный Store/worker/Context/Ollama adapter, FIFO
без перекрытия, completed и память сохранены. Admission/HTTP/WS игрового клиента
здесь не подменяются утверждением о полном показе. Времена очереди/выполнения
получены из сохранённых timestamps; TTFT — от started до первого delta.

## Выбор, офлайн-проверка и границы приёмки

**Основной: gallery-guide-main:a01 = Qwen3 4B Q4_K_M, num_ctx=8192, temperature=0.2.**
Проверенный 4B-профиль укладывается в лимиты с полной историей; окно 8192
оставляет больше VRAM, чем 16384, и вмещает проверенный длинный русский вход.
**Резерв: gallery-guide-reserve:a01 = Qwen2.5 3B Q4_K_M с теми же окном/temperature.**
Он меньше основной модели, быстрее в измеренных сериях и требует меньше VRAM.
Выбор двух профилей основан на измеренном запасе ресурсов и продолжении диалога;
это не автоматический рейтинг фактической точности моделей.

Первоначальный резерв 1.5B заменён: в новом cold vangogh-0 при окне 8192
зафиксирован output_limit (8004 точки, 22,79 с), хотя все 21 тёплых запроса
прошли. Этот начальный запрос не имеет прошлой пары, поэтому сам отказ не
приписывается исправлению ID. Исходный tag/измерения сохранены; 3B уже была
скачана и прошла выбранную матрицу без отказов. Новых скачиваний нет.

В тёплых baseline-сериях 8192 у каждой модели контрольный код 742 встречается
в 6/6 продолжений и в 0/6 чистых историй. Передача полной пары подтверждена
регрессионным тестом, а не только наличием кода в ответе. В 0/6 начальных ответов
каждой модели встретилось явное обозначение реконструкции. У 1.5B наблюдалось
выдуманное название картины, у 4B — метафоры с атрибуцией Леонардо без источника.
Для C01 отдельно проверять факты и следование инструкциям у обоих выбранных
профилей; prompt не гарантирует их соблюдение. Failed/partial не добавляются
в Completed/Summary: после неуспешного начального ответа пара отсутствует.

Локальные manifest digest подготовленных aliases (совпадают с измеренными
bench-aliases 8192):

- main: `01dccbec213a6c7f3483c736f329b0b9e60581c89acfd64e1b0f490ca800a812`;
- reserve: `703752ed70baabf08d8e56c0a86bacf43866ed1eb8b21dded61bae7472eace2d`.

Повторная SQL-очередь со сценой прошла для обоих выбранных tags. Повторный
[offline.sh](../tools/modelbench/offline.sh) остановлен по просьбе пользователя
сократить расход ресурсов. В namespace были только lo и пустые IPv4/IPv6 routes;
production-adapter fixtures основного 4B завершились PASS, а полная матрица
обоих tags не завершена. Для нового резерва 3B офлайн-проверка в этом изменении
не подтверждена. Наличие локальных весов не подменяет отсутствующее измерение.
Прежняя офлайн-проверка сохранена в legacy-архиве и относилась к резерву 1.5B.

**Физические LAN-показ без WAN и localhost-показ с выключенным Wi-Fi ещё не проведены.**
Namespace подтверждает автономность весов/адаптера, но не полный игровой показ
C01/Q02, не сетевую доступность остальных ноутбуков и не бюджет контента frontend.
Сеть Windows не переключалась. При изменении режима GPU/питания/нагрузки/мира
повторить измерения; аппаратные гарантии для иных условий не заявляются.

Defaults и точные команды скачивания, проверки digest, создания aliases и ручного
офлайн-переключения — [DEVELOPMENT.md](DEVELOPMENT.md#a01--подготовка-ollama-в-wsl-ubuntu),
[Modelfile](../configs/ollama/main.Modelfile) и [резерв](../configs/ollama/reserve.Modelfile).
Backend не скачивает модели и не переключает их автоматически; API, миграции,
90/120 секунд и 8000 выходных символов не изменены.
