# Локальные гиды B08

Backend обращается только к настроенному Ollama через `POST /api/chat` с `stream=true`. Транспорт HTTP/NDJSON не знает о БД, личностях или игровых правилах. Usecase собирает контекст; B07 сохраняет очередь, вопрос, завершённый ответ и память. HTTP/WS API не изменён.

## Серверный профиль

В `WORLD_DIR/catalog.json` запись `profiles` связывает ID личности с локальным JSON-файлом. Тот же ID используется в `room.guides[].id`. Все поля обязательны, неизвестные поля, null, повторные ключи и некорректный Unicode отклоняются. Загружаются только обычные файлы внутри WORLD_DIR с существующими ограничениями traversal/symlink/FIFO. Файлы после startup не перечитываются; изменения требуют новой WORLD_VERSION и рестарта.

| Поле | Смысл и предел |
|---|---|
| `personality` | Личность и обозначение реконструкции; 1–2000 кодовых точек |
| `style` | Стиль образовательного диалога; 1–1000 |
| `topic` | Тематика; 1–1000 |
| `constraints` | 1–20 непустых ограничений, каждое до 1000 |
| `materials` | До 100 локальных материалов, допустим пустой массив |
| `materials[].id` | Уникальный в профиле непрозрачный ID по общим правилам |
| `materials[].text` | Подготовленный текст, 1–8000 кодовых точек |
| `materials[].sources` | 1–20 описаний происхождения, каждое 1–1000; ссылки не загружаются |
| `materials[].exhibit_ids` | До 100 ID существующих экспонатов; допустим пустой массив |

Сумма personality/style/topic/constraints — не более 4000 кодовых точек. Пустые/пробельные строки и U+0000 запрещены. Полные примеры: [Леонардо](../examples/guides/leonardo.json) и [Ван Гог](../examples/guides/vangogh.json). Это демонстрационные учебные упражнения, не проверенный образовательный пакет C01 и не готовый мир. Профили и источники серверные, не выдаются клиенту и не увеличивают бюджет контента.

Общие инструкции usecase требуют русского диалога, явного обозначения художественной реконструкции, отказа от придуманных реальных цитат и признания недостатка фактов. Эти инструкции не зависят от текста профиля. Различимость реальных ответов и достоверность материалов проверяются вручную; prompt не гарантирует поведение любой модели.

## Контекст и память

Максимум входа приложения — **16 000 Unicode-кодовых точек** по сумме содержимого сообщений, включая инструкции и текущий вопрос. Это не число токенов. Ollama получает готовую историю сообщений, без SDK, tools или изображений.

Контекст содержит:

- профиль и обязательные инструкции;
- выбранный экспонат: ID и до 1600 кодовых точек названия/описания;
- сохранённую память по `(user_id, guide_id)`, до 4000 кодовых точек;
- до 20 последних личных событий пользователя, порядок `(created_at,id) DESC`, общий текст до 2000 кодовых точек; для известных экспонатов включается короткое описание;
- релевантные материалы: совпадение выбранного экспоната имеет вес 10000, экспоната из личных событий — 100, совпадение слова вопроса длиной от трёх кодовых точек — 1. Равные оценки упорядочены по ID. В модель попадает до 4000 точек текста и 1000 точек источников каждого выбранного материала;
- до четырёх последних completed-пар в хронологическом порядке и полный текущий вопрос.

При превышении бюджета сначала убираются старейшие пары, затем материалы с минимальной оценкой. Сам вопрос и обязательные инструкции не обрезаются. Повторный осмотр обновляет время существующего события, поэтому снова становится актуальным. Старые ID, которых больше нет в текущем мире, остаются метаданными без подмены описаний. Фото — только сохранённые ID/зал/экспонат/время: модель не видит пиксели. Загрузку фото реализуют B09/B10.

После успешного ответа память обновляется детерминированно из последних четырёх completed-пар: до 240 точек вопроса и 700 точек ответа на пару, общий предел 4000. Это выдержки, а не семантическое LLM-summary. Ответ, статус completed и память фиксируются одной SQL-транзакцией; version памяти увеличивается только победителем терминального перехода. Failed/cancelled/partial не меняют память. Уже сохранённая память B07 совместима: читается с ограничением длины, при следующем completed заменяется новым форматом. Миграция не требуется.

## Отказы и ограничения

Выполнение, включая сборку контекста, ограничено 90 секундами от started_at; очередь — 120 секундами. HTTP connect имеет предел 5 секунд, ожидание заголовков — 10 секунд. Timeout → `AI_TIMEOUT`; недоступность, HTTP-ошибка, повреждённый NDJSON, запись более 256 КиБ или EOF без done → `AI_UNAVAILABLE`; ответ более 8000 кодовых точек либо `done_reason=length` → `AI_OUTPUT_LIMIT`. Partial передаётся только в delta, не становится историей/памятью. Ошибка сохранения завершения закрывает WS с 1011 по правилам B07.

Отмена запроса закрывает HTTP body; worker дожидается завершения адаптера перед следующей генерацией. Env proxy и HTTP redirect отключены. Backend не скачивает модели, не выбирает запасной tag и не проверяет доступность Ollama при старте: прогулка и HTTP-история работают без LLM. Полные prompts, ответы и тела ошибок модели не логируются.

## Проверка с настоящей моделью

Сначала завершить A01: подготовить основной/резервный tags и токенное окно на реальном ноутбуке. `OLLAMA_MODEL` задаёт точный подготовленный tag; backend не переопределяет его num_ctx. Настройку окна включить в подготовленную конфигурацию модели по результатам A01. Все модели и инструменты скачать до отключения интернета.

Независимая от готового мира проверка fixture-профилей:

```sh
B08_OLLAMA_MODEL="$OLLAMA_MODEL" B08_OLLAMA_URL="$OLLAMA_BASE_URL" \
  go test ./internal/adapters/outbound/ollama -run '^TestLocalModelFixtures$' -count=1 -v
```

Этот opt-in тест последовательно задаёт два вопроса каждой личности, передаёт completed-пару и детерминированную память во второй вопрос, проверяет отсутствие ошибок и соблюдение output limit. Он выводит только длину/время, не prompts или диалоги. Без B08_OLLAMA_MODEL явно пропускается. Персистентность и WS отдельно проверяют автоматические тесты с PostgreSQL и fake NDJSON.

Ручная приёмка на подготовленном мире C01: подключить два аккаунта по Wi-Fi без интернета; осмотреть экспонат, спросить обеих личностей о свете/цвете, продолжить разговор после reconnect и restart backend. Убедиться, что ответ учитывает личный осмотр/разговор, другой аккаунт их не знает, роли различимы и реконструкция обозначена. Затем выключить Wi-Fi сервера и повторить через localhost. Зафиксировать точный tag/окно, длительности, режим подключения, фактические ответы в приватном отчёте проверяющего и итог каждого критерия.

**Статус реального показа: не выполнен в среде разработки B08.** Здесь нет установленного Ollama, подготовленной модели A01 и готового мира C01; качество ответов, GPU-производительность и два офлайн-режима не подтверждены. Не заменять этот статус результатами fake-тестов.
