# Образовательная картинная галерея C01

Готовый пакет: [`content/world`](../../content/world). Версия: `gallery_c01_v1`.
Авторская экскурсия на русском языке: сравнить композицию, свет, цвет и мазок
на конкретных картинах трёх направлений и обосновать своё впечатление.

## Маршрут

24 зала по три репродукции, 72 локальных JPEG. В их числе лицевая и расписанная
оборотная стороны портрета Джиневры де Бенчи: это две разные учебные поверхности
одного произведения, а не два портрета. Все изображения имеют собственное
содержание и используются экспонатами; повторных изображений и padding нет.

| Гид и раздел | Тематические залы по порядку |
|---|---|
| Леонардо да Винчи — Возрождение | Лицо и характер; Пейзаж за фигурой; Построение пространства; Светотень и объём; Фигура в пространстве; Жест и отношения; Равновесие композиции; Деталь и материал |
| Клод Моне — импрессионизм | Утро и воздух; Дневной свет; Вечер над рекой; Вода и отражения; Сад как мастерская; Город и современная жизнь; Снег и перемена погоды; Один мотив — разные впечатления |
| Винсент ван Гог — постимпрессионизм | Автопортрет и художественный образ; Человек и цвет; Натюрморт: цвет и предмет; Деревня и постройки; Поле и ритм; Деревья и движение взгляда; Предметы и повседневная жизнь; От наблюдения к выразительному цвету |

Переходы последовательные и обратимые: первый и последний залы имеют по одному
выходу, остальные — по два. Начало — портретный зал Леонардо. У дверей указаны
темы соседей. Пример короткого показа: портрет Джиневры → объяснение светотени;
переходы к Моне → сравнение фасадов собора; у Ван Гога → сравнение автопортретов.
Для полноценного маршрута не требуется просмотр всех картин за один сеанс.

В каждом зале 12 × 12 × 4 м есть пол, четыре стены, три картины на северной стене
лицом к +Z и один художник-гид. Старт `(6,0,6)`, направленные spawns `(2,0,6)`
и `(10,0,6)`. Двери — точки перед сплошными стенами: движение через стены
невозможно, смена зала выполняется командой. К каждому объекту есть свободный
путь и LOS; размеры плоскостей сохраняют пропорции музейных изображений.

## Материалы и права

[`content/gallery.json`](../../content/gallery.json) — локальный кураторский
источник: темы, вопросы, педагогические заметки, русские названия и авторство,
оригинальные музейные названия/атрибуции, датировки, техника, музейные номера,
credit lines, URL объекта/изображения, исходные размеры, права, байты и SHA-256.
Английские Visual Description взяты из `published_images.csv.assistivetext`
того же CC0 dataset, а не скопированы по разрешению на фотографии сайта;
точные URL CSV, SHA-256 исходных выгрузок и ссылка на лицензию закреплены в
кураторском JSON. Краткие русские ориентиры демонстрационных картин написаны
самостоятельно по этим описаниям.
Русские названия — редакционные переводы; оригинальные названия сохранены для
сверки. Датировки и техники передаются без выдуманной точности.

Все репродукции получены из [NGA Open Data](https://github.com/NationalGalleryOfArt/opendata)
(`objects.csv`, `published_images.csv`), только записи `viewtype=primary`,
`openaccess=1`, `classification=Painting`. Изображения доступны по
[NGA Open Access](https://www.nga.gov/artworks/free-images-and-open-access):
public domain, разрешено коммерческое и некоммерческое использование.
Права проверены по признаку каждой опубликованной репродукции; общественное
достояние автора само по себе не использовалось как разрешение на произвольный
снимок. National Gallery of Art не является автором или заказчиком проекта.

JPEG получены через музейный IIIF: `full/!4096,4096/0/default.jpg`, либо меньший
предел при меньшем оригинале. Это разрешение позволяет изучать детали.
Локального увеличения, перезаписи качества ради байтов, шумовых картинок и
синтетических замен картин нет. Разрешение, URL и hash закреплены для каждого
файла; не требуется скачивание при запуске игры. Повторное получение по URL
должно сверяться с hash: музей может обновить цифровой файл.

Описания, упражнения и учебные интерпретации написаны для C01; они не являются
цитатами исторических художников. Серверные профили находятся в `world/profiles`.
Три личности имеют разные способы объяснения и поэкспонатные знания с источниками.
Художник обсуждает также других мастеров своего направления с явным указанием
авторства. Обобщение направления и позднейшие сравнения — голос учебной
реконструкции, а не подлинное воспоминание человека. Ссылки нужны для аудита;
backend не открывает их и не передаёт профиль клиенту.

## Точные размеры

Полный воспроизводимый отчёт: [budget.json](budget.json). Он содержит байты и
SHA-256 каждого используемого JPEG, байты/hash JSON, пакет каждого зала,
консервативный размер snapshot и остаток после резерва фото.

- Изображения: **317 689 137 байт**.
- JSON всех залов: **117 401 байт**.
- `total_content_bytes`: **317 806 538 байт**.
- `floor(total / 10)`: **31 780 653 байта**.
- Самый большой пакет: **18 390 848 байт**, зал сада Моне.
- С резервом фото: **18 390 848 + 3 145 728 = 21 536 576 ≤ 31 780 653**.
- Минимальный запас по всем залам: **10 244 077 байт**.

Индекс, профили, кураторские записи и этот отчёт в знаменатель не входят.
Все 24 пакета удовлетворяют неравенству; полный список — в JSON-отчёте.
Декодированная память браузера/GPU учитывается отдельно: файловые байты не
означают размер текстур. Каталог держит исходные файлы в RAM; при подготовке
серверного ноутбука учитывать копии при startup и временное декодирование.

## Воспроизведение и обновление

Из корня репозитория, с Go из `go.mod`:

```sh
make world-check
go run ./tools/worldcheck -dir content/world -version gallery_c01_v1 > /tmp/c01-budget.json
cmp docs/content/budget.json /tmp/c01-budget.json
# Авторская подготовка; Python 3.9+ нужен только для этого офлайн-инструмента.
python3 tools/prepare-gallery.py --output /tmp/gallery-c01-rebuilt
diff -qr content/world /tmp/gallery-c01-rebuilt
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tools -p test_prepare_gallery.py
```

Подготовщик читает кураторский JSON и локальные assets, сначала проверяет hashes
и размеры, затем создаёт только новый каталог. Сети и дополнительных Python-
пакетов ему не нужно. Ошибка SHA/байтов или существующий output запрещают сборку;
работающий мир он не перезаписывает. Для утраченного asset получите файл по
`image_url`, проверьте `sha256` и верните его в указанный `file` до подготовки.

При изменении картины, текста, геометрии или профиля: изменить исходные данные/
подготовщик, присвоить новую `world_version`, собрать отдельный каталог,
проверить его `worldcheck`, обновить отчёт и проверки ожидаемой версии, затем
установить каталог и перезапустить backend с совпадающим `WORLD_VERSION`.
Сохранить exhibit ID для того же произведения; не переиспользовать его для другого.
Локальные учебные metadata не заменяют проверку прав нового изображения.

## Приёмка

`go test ./tools/worldcheck` проверяет готовый мир, точные байты/hash, отсутствие
дубликатов, полноту знаний всех гидов, источники, связность, spawns, свободные
маршруты к взаимодействиям и LOS. Отчёт проверяется на совпадение с файлами.
Изменение публичной формы Room, валидатора, SQL и генерации ответов не требуется.

Опциональная проверка настоящей модели на трёх профилях:

```sh
C01_OLLAMA_MODEL="$OLLAMA_MODEL" C01_OLLAMA_URL="$OLLAMA_BASE_URL" \
  C01_ANSWERS_FILE=/tmp/c01-private-answers.jsonl \
  go test ./tools/worldcheck -run '^TestLocalModelGallery$' -count=1 -v
```

Файл ответов должен отсутствовать; создаётся с правами 0600 и не коммитится.
Тест задаёт каждой личности два синтетических вопроса с выбранной картиной.
Продолжение адресует конкретные музейные номера из того же зала; assertion
проверяет наличие полного предыдущего ответа в собранном контексте. Общие
вопросы могут вытеснять completed-пары по штатным правилам B08; Summary
остаётся ограниченной выдержкой, а не полной историей. В stdout только длина и время.
Без `C01_OLLAMA_MODEL` явно пропускается. Успех транспорта не доказывает
достоверность ответа: вручную сверить автора/дату, обозначение реконструкции,
различимость стиля, отсутствие вымышленных цитат и чужого авторства.
Фактические результаты — [ACCEPTANCE.md](ACCEPTANCE.md).

Два браузерных показа (LAN без интернета, затем localhost с выключенным Wi-Fi),
FPS и совместная VRAM/RAM требуют frontend и выполняются по Q02. Автотест
каталога и текстовый запрос к модели не заменяют эти показы.
