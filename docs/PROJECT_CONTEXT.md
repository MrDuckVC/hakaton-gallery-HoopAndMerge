# Контекст проекта

Разработка ведётся только по Clean Architecture: domain <- usecase <- adapters. Зависимости направлены внутрь, реализации связывает cmd/server. Требование обязательно и для MVP; обход слоёв ради сроков запрещён. Подробности — docs/ARCHITECTURE.md (для файлов в docs/ — ARCHITECTURE.md).

Два разработчика, два дня по восемь рабочих часов. Отдельные frontend- и backend-репозитории. Этот репозиторий — исключительно backend на Go. Клиенты Three.js подключаются по LAN/Wi-Fi. Интернет во время игры отсутствует.

Обязательные возможности первого дня: сессии; защищённый WebSocket; другие игроки и чат; загрузка залов по подтверждённой позиции; бюджет кеша не более 10%; локальная LLM; индивидуальность и сохранённая память гидов; восстановление состояния из PostgreSQL.

Фотографии с загрузкой, альбомом и публикацией — второй день. В первый день фронтенд может скачивать кадр без backend API фотографий.

Стек: Go net/http, PostgreSQL, pgx/v5, coder/websocket, локальный Ollama по HTTP. Версии зависимостей фиксируются в go.mod/go.sum после проверки совместимости с фактическим проектом. Не копировать номера версий из переписки без проверки. Внешние облачные API запрещены в игровом runtime.

RTX 4070 Laptop обслуживает одну общую локальную модель. Персонажи различаются инструкциями, знаниями и памятью, а не отдельными загруженными моделями. Модель выбирается после замера VRAM и скорости; model tag задаётся конфигурацией. Базовый кандидат Qwen семейства 4B, меньшая модель — резерв. Нет требования распознавать содержание фотографий.

Польза: изучение истории и искусства через разговоры и совместную фотоэкскурсию. Гиды — художественные реконструкции, опирающиеся на подготовленные материалы. Не приписывать реальные цитаты без источника.

За пределами MVP: VR-шлемы, голос, публичный интернет-хостинг, несколько миров, торговля, полноценная физика, микросервисы, Redis, векторная БД, агентные фреймворки.

Открытые вопросы для организаторов: что входит в знаменатель данных мира; считается ли декодированная память; правила учёта фотографий. До уточнения клиент должен ограничивать отдельно и контент мира, и фото, включать резерв загрузок и не создавать постоянный кеш. Backend гарантирует корректные размеры и выдачу по положению; он не может контролировать память произвольного браузерного клиента.
